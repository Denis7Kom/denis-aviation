# Проверка безопасности — 30 октября 2026 года

Проверены опубликованный исходный код сайта, файл правил Firestore в репозитории,
Worker уведомлений и локальные зависимости. Это не полный аудит Firebase, Cloudflare,
GitHub-аккаунта или всех версий браузеров. Секреты и действующие заявки не использовались.

## Исправления и проверки

- Правила Firestore отклоняют дату с месяцем или днём вне допустимого диапазона и
  время с часом или минутой вне диапазона. Для календарных сочетаний и прошедшей даты
  остаются ограничения, описанные в [руководстве](requests-and-notifications.md#правила-firestore).
- Отдельные тесты запускают правила из репозитория в Firestore Emulator с тестовыми
  пользователями. Проверяется прямое чтение и отмена чужой заявки, доступ владельца,
  статус и личность администратора, допустимые поля и запрет удаления. Инструкция по
  запуску есть в [README](../README.md#verification); эти тесты выполняются также в CI.
- Страница заявок задаёт частичную политику Content Security Policy, запрещающую
  установку базового URL через `base` и загрузку через `object`. Она не ограничивает
  источники скриптов и не защищает от встраивания страницы в чужой iframe.
- Обновлённый Worker сообщает имена отсутствующих привязок без их значений и обрабатывает
  некорректный сервисный аккаунт. Реальная доставка в Telegram не подтверждена.

## Что ещё проверить в действующих сервисах

1. Сравнить опубликованные правила Firebase с [`firestore.rules`](../firestore.rules),
   сохранить все нужные правила других коллекций и опубликовать исправленные правила.
   GitHub Pages не развёртывает правила Firestore. Тесты эмулятора подтверждают поведение
   файла, а не настройки действующего проекта.
2. Firebase Rules не ограничивают число заявок от вошедшего пользователя. При росте
   нагрузки понадобится отдельно спроектировать защиту от спама и расходования квоты.
   Проверить разрешённые способы входа в Firebase Authentication.
3. По данным GitHub API на дату проверки защита ветки `main` не включена. Проверить
   настройки ветки и rulesets в GitHub и включить обязательные проверки там, где это
   поддерживается тарифом и соответствует рабочему процессу владельца.
4. При проверке ответов GitHub Pages не обнаружены заголовки CSP, `X-Frame-Options` и
   `X-Content-Type-Options`. CSP в HTML даёт только частичную защиту; например, запрет
   встраивания нужно задавать HTTP-заголовком на хостинге. Перед добавлением строгой
   политики скриптов необходимо проверить вход через Google и остальные функции сайта.
5. Проверить действующие права Google Cloud service account и привязки Worker без
   публикации их значений. Серверные учётные данные работают через IAM и обходят
   клиентские правила Firestore. Подтвердить Telegram отдельным тестовым запросом,
   если к нему вернутся; см. [инструкцию Worker](../telegram-notifier/README.md).

Данные заявки в браузерном уведомлении могут быть видны на экране блокировки или в
центре уведомлений. Оповещение зависит от открытой страницы и разрешения браузера;
см. [руководство](requests-and-notifications.md#оповещение-на-сайте).
