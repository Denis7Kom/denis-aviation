# Будущая система заявок на полёты и диспетчерский контроль

Статус: идея на будущее, не реализована.

## Цель

Посетитель оставляет заявку на совместный полёт или диспетчерский контроль прямо на сайте. Денис просматривает заявки в закрытом разделе сайта, меняет их статус и получает уведомление о новой заявке.

## Предполагаемый сценарий

- Форма содержит тип заявки, сеть, дату и время с часовым поясом, ник или позывной, маршрут или аэропорт, контакт для ответа и дополнительные сведения.
- После успешного сохранения сайт подтверждает приём заявки; при ошибке показывает понятное сообщение.
- В закрытой панели отображаются заявки с фильтром по статусу.
- Предлагаемые статусы: новая, рассматривается, подтверждена, отклонена и завершена.
- Уведомление владельцу: Telegram или электронная почта; окончательный выбор и способ подключения ещё не определены.
- Нужно решить, должен ли посетитель видеть статус заявки и как безопасно предоставить ему доступ: через учётную запись или индивидуальную защищённую ссылку.

## Возможная реализация

- Сайт остаётся на GitHub Pages.
- Firebase Cloud Firestore хранит заявки, Firebase Authentication обеспечивает вход администратора.
- Правила Firestore разрешают посетителям создавать только корректные заявки; чтение и изменение всех заявок доступны только авторизованному администратору. Прямой доступ посетителей к заявкам других людей запрещён.
- Для защиты от спама нужны проверка входных данных и ограничение запросов; механизм ограничения и серверной проверки необходимо выбрать при реализации.
- Автоматическое уведомление требует доверенной серверной логики. Варианты: Cloud Functions на тарифе Blaze с подключённым биллингом либо подходящий внешний сервис. Токен Telegram и другие секреты нельзя размещать в открытом репозитории или коде сайта.
- Текущая форма использует подготовленное письмо через почтовое приложение; до реализации базы данных эта механика остаётся прежней.

## Стоимость и ограничения

На момент обсуждения Firebase Firestore имел бесплатную квоту. Перед реализацией нужно заново проверить тарифы, лимиты, требования к биллингу и доступность выбранного сервиса уведомлений. Не подключать платные сервисы без отдельного согласования.
